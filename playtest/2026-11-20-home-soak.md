# 家服耐久测试（soak）报告 · 2026-11-20

家服 Claude 跑的 `npm run soak`（`tests/soak/soak.spec.ts`）。原始数据：
[`data/2026-11-20-home-soak/soak.json`](data/2026-11-20-home-soak/soak.json)（每局一行 + 每 10 局一次 GC 后采样），

## 1. 结论

**209 局连续不刷新，没有泄漏迹象，0 个页面错误 / console 错误。** 计划 300 局，跑到第 209 局时
因家服 CPU 被占满，按用户要求在 16:32（北京时间）中断。Playwright 记为 `interrupted`，不是失败。
测试末尾的断言没机会执行，下表按 spec 里同样的阈值手算。

| 指标（第 10 局起，GC 后） | 实测 | 阈值（spec） | 判定 |
|---|---|---|---|
| 页面错误 + console 错误 | 0 | 0 | ✅ |
| documents | 始终 1 | = 1 | ✅ |
| DOM 节点 | 168 → 168（第 10–200 局完全不变） | 极差 ≤ 30 | ✅ |
| JS 事件监听 | 60 → 60（完全不变） | 极差 ≤ 10 | ✅ |
| 堆内存 | 4.96 MB（第 10 局）→ 5.25（第 40 局）→ 5.32（第 200 局），峰值 5.41 | 斜率 < 15 KB/局 | ✅ 1.23 KB/局 |
| 各关 JS 帧耗时 p95（每局取最大关，按局取中位数） | 前 1/10：0.8 ms，后 1/10：1.1 ms | 后 < 前 × 1.5 + 1 = 2.2 ms | ✅ |

- 堆内存的斜率几乎全部来自前 40 局的预热（4.96 → 5.25）。第 40 到 200 局之间在 5.23–5.37 MB 波动，
  看不出趋势。即使按 1.23 KB/局外推，展台一整天也只多几百 KB。
- 帧耗时从 0.8 涨到 1.1 ms 的这段时间，家服整机负载在 14–18（12 核），其他服务也在抢 CPU。
  原因没有拆开（单样本，不归因）。真 GPU 上的帧耗时以 MBP 实测为准（`2026-11-20-mbp.md`）。
- 单局 JS 帧耗时峰值超过 20 ms 的，只有**第 1 局**：202 ms。这就是 `2026-11-20-home-m4.md`
  §3.1 记的首次使用材质卡顿，后面 208 局再没出现过。被测的是 Junie 任务 #1 之前的代码，
  预热修复（`6d69f07`）还没包含在内。
- 帧间隔 p95 的中位数是 50 ms：SwiftShader 在 1280×720 下大约 20 fps，这只反映软件渲染有多慢，不是游戏的问题。

## 2. 跑了什么

- **被测代码**：`6ccd80b`（即重写历史前的 `dd1abfc`，M4 交接点），`src/` 与 `tests/` 与当时完全一致。
  **不含** Junie 任务 #1（`5efdd5a`…`7b65015`，`src/` 改了 7 个文件）。
- **环境**：家服 Linux，Playwright 1.60 / chromium-headless-shell 1223，SwiftShader，1280×720，
  单页面、单 worker、整个过程不刷新。trace / 截图 / 录像全关。
- **玩法轮换**（`run % 3`）：

  | 风格 | 局数 | 高度中位数 | 击中无人机中位数 |
  |---|---:|---:|---:|
  | skilled（认真玩） | 69 | 19,805 | 28 |
  | sloppy（抢跑、点空、反应慢） | 70 | 4,082 | 16 |
  | idle（完全不操作） | 70 | 0 | 0 |

- **保存路径**：每 10 局有 1 局停在结果页不输名字，靠 25 秒超时自动保存（共 20 局，全部存上）；
  其余 189 局走输入缩写的流程。
- **用时**：209.8 分钟，每局约 1.0 分钟。

## 3. 没覆盖到的

- **Junie 任务 #1 之后的 `src/`**：其中 AudioContext 改为挂载时创建、首帧预热所有程序、彗星锁定宽限等
  改动都没有经过耐久测试。看改动形态，它们都只在页面里发生一次或在每局里重复用同一批对象，
  预计不会引入逐局泄漏（这是推断，未实测）。要补的话，建议在夜间用 `nice -n 19` 跑 60–100 局，
  或者在 MBP 真机上用 `bot_mbp.py` 跑 soak。
- **显存 / 驱动层泄漏**：SwiftShader 看不到。只能在真机上长时间开着观察。
- **跨天运行**：IndexedDB 里会越积越多（本次存了 209 局）。DOM 节点不变，说明排行榜只渲染前 N 名，
  但多日累积后读取库的耗时没有测。
- **300 局的后 91 局**：没跑。前 200 局的各项曲线都是平的，补跑的信息增量很低。
